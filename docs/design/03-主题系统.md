# 03 主题系统设计

> 目标:用户不改代码即可深度定制外观。三大支柱:**模板层级继承**、**theme.json 设计令牌(设计系统 API)**、**Setting 声明式配置面板**。

## 1. 主题目录结构

```
themes/mytheme/
├── theme.json          # 元数据 + 设计令牌 + 配置声明(核心文件)
├── templates/          # 模板(纯 PHP,只 echo 转义后的变量)
│   ├── index.php
│   ├── post.php
│   ├── page.php
│   ├── archive.php
│   ├── comment-list.php
│   └── partials/header.php
├── assets/
│   ├── theme.css       # 只消费 CSS 变量,不写死颜色
│   └── theme.js
└── screenshot.png
```

## 2. 模板层级继承(WordPress 式 + 子主题)

解析顺序,自上而下第一个命中即用:

```
1 子主题 templates/{type}.php        # 子主题可只覆盖单文件
2 本主题 templates/{type}.php
3 父主题 templates/{type}.php        # theme.json 声明 extends: "default"
4 内核保底模板 fallback/{type}.php   # 保证任何主题都能渲染
```

- `{type}` 由路由解析:单篇文章→`post`,列表→`archive`,首页→`index`,404→`404`。
- 子主题机制:仅声明 `extends` + 放需要覆盖的文件,升级父主题不丢定制。
- 模板内只允许调用公开 API 与辅助函数(`e()` 转义、`asset_url()`、`the_title()`),禁止直接 SQL。

## 3. theme.json:设计系统 API

主题的外观令牌全部集中在 theme.json,内核将其编译为 CSS 变量注入 `<head>`,并提供给后台渲染器。

```json
{
  "name": "mytheme",
  "version": "1.0.0",
  "extends": "default",
  "author": "...",
  "tags": ["minimal", "dark"],
  "tokens": {
    "color": {
      "primary": "#6D28D9",
      "background": "#FFFFFF",
      "text": "#1F2937",
      "muted": "#6B7280"
    },
    "typography": {
      "fontFamilyBase": "system-ui, sans-serif",
      "fontFamilyHeading": "Georgia, serif",
      "fontSizeBase": "clamp(1rem, 0.95rem + 0.25vw, 1.125rem)",
      "lineHeightBody": 1.7
    },
    "spacing": { "unit": "0.5rem", "contentMaxWidth": "72ch" },
    "radius": { "sm": "4px", "md": "8px" }
  },
  "darkMode": { "strategy": "class", "tokens": { "color.background": "#111827" } },
  "settings": [ /* 见第 5 节 */ ]
}
```

编译产物:

```css
:root { --color-primary:#6D28D9; --font-body: ...; --space-unit:.5rem; --content-max:72ch; }
.theme-dark { --color-background:#111827; }
```

- 主题 CSS **只允许引用变量**,保证用户改令牌即改全站外观 —— 这就是"高自定义"的落点。
- `darkMode.strategy`: `media`(跟随系统)/ `class`(后台开关),令牌按策略覆盖。

## 4. 主题生命周期

| 动作 | 内核行为 |
|---|---|
| install(上传/目录发现) | 校验 theme.json schema、检查 `extends` 链、复制入库注册 `kind: Theme` |
| activate | 写 Options `active_theme`;派发 `theme.activated`;失效模板/令牌缓存 |
| deactivate | 仅当非当前主题允许;派发 `theme.deactivated` |
| uninstall | 删除该主题的 Options 命名空间 `theme.{name}.*`;Secret 不动;模板文件保留待确认 |

- 保底:内核 fallback 模板永远存在,主题损坏时自动回退并告警,前台不白屏。

## 5. Setting 声明式配置面板(Halo 模型)

主题在 theme.json 里声明配置项,后台**自动渲染表单**,无需主题写任何管理代码:

```json
"settings": [
  { "name": "show_excerpt", "type": "boolean", "label": "列表显示摘要", "default": true },
  { "name": "post_per_page", "type": "number", "label": "每页文章数", "default": 10, "min": 3, "max": 50 },
  { "name": "footer_text", "type": "textarea", "label": "页脚文字" },
  { "name": "layout", "type": "radio", "options": ["list", "grid"], "label": "列表布局", "default": "grid" }
]
```

- 存储:Options 表,键 `theme.{name}.{setting}`,读取带类型转换与默认值兜底。
- 模板端:`$app->theme()->option('layout')`;REST 端:`GET /api/v1/themes/{name}/settings`(Secret 类型除外)。
- 支持 `condition`(依赖其他项显示/隐藏),表单渲染器按声明生成。

## 6. 主题端公开 API

主题通过统一门面访问数据,命名规则 `api.{group}`:

```php
$app->api()->posts(['status'=>'published','page'=>1])   // Widget 查询层别名
$app->api()->categories()
$app->api()->settings('layout')
$app->api()->user()                                       // 当前访客/登录用户(脱敏)
```

- 公开对象一律是**只读 DTO**;主题不能拿到原始实体写数据(写操作只属于后台与 API)。
- 可用 kind 白名单由内核声明(`posts/categories/tags/pages/comments/menu`),插件注册的 kind 需显式 `public: true` 才对主题可见。

## 7. 菜单(Widget Menu)

- 菜单是 Extension(`kind: Menu`),条目引用对象(post/category/page/url)。
- 主题调用 `$app->api()->menu('primary')` 渲染;主题系统不发明菜单数据,只提供渲染辅助。
