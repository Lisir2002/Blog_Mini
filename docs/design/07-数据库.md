# 07 数据库设计

> 双方言(MySQL 8 / SQLite 3.35+)兼容的唯一差异处是仓储层(`SqlDriver`)。表结构以 ANSI 可表达为基线,方言差异全部收敛到驱动实现。

## 1. 核心表清单

| 表 | 归属 | 说明 |
|---|---|---|
| users | Auth | 账号、密码哈希、角色 |
| sessions / personal_access_tokens | Auth | 会话与 PAT(存哈希) |
| extensions | 内核 | Extension 文档统一存储(kind/uid/spec/status JSON) |
| posts / categories / tags / post_categories / post_tags | Content | 内容主表(冗余关键列便于索引) |
| comments | Content | 评论(含审核状态) |
| options | 内核 | 键值设置(命名空间隔离) |
| secrets | 内核 | 敏感凭据 |
| notifications | 通知 | 站内信收件表 |
| notification_events | 通知 | 状态机轨迹(追加日志) |
| notification_preferences | 通知 | 偏好一等实体(schema 版本化) |
| notification_templates | 通知 | 模板(channel+locale) |
| webhooks / webhook_deliveries | API | 出站订阅与投递记录 |
| migrations | 内核 | 迁移版本账本 |

> posts 等高频查询对象采用"**extensions 文档表 + 投影关系表**"双写:API 读扩展文档,列表页走投影表索引;投影在事务内同步更新。

## 2. 关键表结构(基线 SQL,双方言通用)

```sql
CREATE TABLE users (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,  -- MySQL: INT AUTO_INCREMENT
  username      VARCHAR(64)  NOT NULL UNIQUE,
  email         VARCHAR(255) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,              -- password_hash(), Argon2id 优先
  display_name  VARCHAR(64)  NOT NULL,
  role          VARCHAR(32)  NOT NULL DEFAULT 'subscriber',  -- 不用 ENUM(见 §4)
  created_at    TIMESTAMP    NOT NULL,              -- 服务端统一 UTC
  updated_at    TIMESTAMP    NOT NULL
);

CREATE TABLE posts (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  uid          VARCHAR(64) NOT NULL UNIQUE,         -- 对应 extensions.uid
  user_id      INTEGER NOT NULL REFERENCES users(id),
  title        VARCHAR(255) NOT NULL,
  slug         VARCHAR(255) NOT NULL UNIQUE,
  body_md      TEXT NOT NULL,
  body_html    TEXT NOT NULL,                       -- 渲染缓存,发布时生成
  excerpt      VARCHAR(500),
  status       VARCHAR(16) NOT NULL DEFAULT 'draft'
               CHECK (status IN ('draft','published','archived')),
  published_at TIMESTAMP, created_at TIMESTAMP NOT NULL, updated_at TIMESTAMP NOT NULL,
  deleted_at   TIMESTAMP                            -- 软删除
);
CREATE INDEX idx_posts_list ON posts(status, published_at DESC);
CREATE INDEX idx_posts_user ON posts(user_id, status);

CREATE TABLE comments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  post_id  INTEGER NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  user_id  INTEGER REFERENCES users(id),
  author_name VARCHAR(64), author_email VARCHAR(255),
  parent_id INTEGER REFERENCES comments(id),
  body TEXT NOT NULL,
  status VARCHAR(16) NOT NULL DEFAULT 'pending'
         CHECK (status IN ('pending','approved','spam','trash')),
  created_at TIMESTAMP NOT NULL
);
CREATE INDEX idx_comments_post ON comments(post_id, status, created_at);

CREATE TABLE notifications (
  id BIGINT PRIMARY KEY AUTOINCREMENT,
  recipient_id INTEGER NOT NULL,
  category  VARCHAR(32) NOT NULL,
  template_key VARCHAR(64),
  title  VARCHAR(255) NOT NULL, body_html TEXT NOT NULL,
  read_at TIMESTAMP, archived_at TIMESTAMP,
  created_at TIMESTAMP NOT NULL
);
CREATE INDEX idx_notif_inbox ON notifications(recipient_id, created_at DESC);  -- 05 §8

CREATE TABLE notification_preferences (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  scope   VARCHAR(16) NOT NULL CHECK (scope IN ('system','category','type')),
  category VARCHAR(32) NOT NULL DEFAULT '*',
  channels TEXT NOT NULL,          -- JSON 数组
  quiet_hours TEXT,                -- JSON {start,end,tz}
  schema_version INTEGER NOT NULL DEFAULT 1
);
CREATE UNIQUE INDEX idx_pref_unique ON notification_preferences(user_id, scope, category);

CREATE TABLE options (
  name  VARCHAR(191) PRIMARY KEY,   -- utf8mb4 下 191*4<767 索引上限
  value TEXT NOT NULL,              -- JSON 编码(带类型)
  updated_at TIMESTAMP NOT NULL
);

CREATE TABLE extensions (
  uid VARCHAR(64) PRIMARY KEY,
  kind VARCHAR(64) NOT NULL, name VARCHAR(191) NOT NULL,
  api_version VARCHAR(32) NOT NULL,
  spec TEXT NOT NULL, status TEXT,
  creation_timestamp TIMESTAMP NOT NULL,
  UNIQUE (kind, name)
);
CREATE INDEX idx_ext_kind ON extensions(kind);
```

## 3. 方言差异清单(全部封装在 Driver 内)

| 差异 | MySQL | SQLite | 收敛方式 |
|---|---|---|---|
| 自增 | `INT AUTO_INCREMENT` | `INTEGER PRIMARY KEY AUTOINCREMENT` | Driver 建表模板 |
| 当前时间 | `NOW()` | `datetime('now')` | 业务层不写时间函数,PHP 生成 UTC 字符串传入 |
| ENUM | 支持但难变更 | 无 | **统一 VARCHAR + CHECK**(MySQL8 也照此) |
| 字符集 | `utf8mb4/utf8mb4_unicode_ci`,InnoDB | 默认 UTF-8 | 连接 DSN/建库模板 |
| UPSERT | `ON DUPLICATE KEY UPDATE` | `ON CONFLICT DO UPDATE` | `repo->upsert()` |
| 全文检索 | `FULLTEXT`(可选) | FTS5(可选) | 搜索子系统接口,缺省 LIKE 兜底 |
| 外键 | 默认开 | 需 `PRAGMA foreign_keys=ON` | 连接建立即执行 |
| 并发 | 多写者 | WAL 单写者 | SQLite 强制 WAL + busy_timeout |

## 4. 设计约定

- 时间戳一律 `TIMESTAMP`/`TEXT` 存 **UTC**,展示层按用户时区转换;不用数据库时间函数。
- 软删除:`deleted_at`(内容类)/`archived_at`(通知类),查询默认过滤。
- 大文本(Markdown/HTML)放主表即可(博客量级),不做垂直拆分;附件走文件系统+`attachments` 元数据表。
- JSON 列在 MySQL 用 `JSON`,SQLite 用 `TEXT`,应用层编解码(不依赖数据库 JSON 函数)。
- 表名前缀可配置(安装向导),SQL 模板经 `TablePrefix` 替换。

## 5. 迁移机制

- `migrations` 表记录已应用版本;迁移文件 `database/migrations/{ts}_{name}.php`,up()/down() 成对。
- 迁移 DSL 基于 Driver 抽象:`$m->create('posts', fn(Table $t) => ...)`、`$t->enum(...)` 实际生成 VARCHAR+CHECK。
- 首次安装 = 运行全部迁移;升级 = 按序补跑;失败回滚事务(SQLite DDL 事务安全,MySQL 注意 DDL 隐式提交,拆分步骤)。
- 内核版本与 schema 版本双记录,升级前要求备份(`storage/backups/`)。

## 6. 仓储层职责(唯一允许裸 SQL 之处)

```php
interface SqlDriver {
    public function insertReturningId(string $table, array $data): int;
    public function upsert(string $table, array $data, array $conflictCols): void;
    public function paginate(SelectSql $q, int $size, ?string $cursor): Page;  // 06 §4
    public function now(): string;   // 仅测试/回填使用
}
```

- 上层业务只调仓储方法;白名单校验排序列/表名(占位符不能用于标识符)。
- 集成测试统一跑内存 SQLite(`sqlite::memory:`,setUp 建表),MySQL 兼容性由 CI 矩阵覆盖。
