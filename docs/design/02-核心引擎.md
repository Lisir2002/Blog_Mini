# 02 核心引擎设计(Kernel)

> 内核只做四件事:**容器、事件、路由、Extension 注册**。所有子系统(主题/插件/通知/内容)都挂载在这四件之上,内核自身不依赖任何子系统。

## 1. 服务容器(Container)

轻量 DI 容器,不做注解扫描,只做"接口/名字 → 工厂"的显式注册。

```php
final class Container
{
    /** @var array<string, callable> */
    private array $factories = [];
    /** @var array<string, object> */
    private array $instances = [];

    public function singleton(string $id, callable $factory): void;  // 懒解析+共享
    public function bind(string $id, callable $factory): void;      // 每次新建
    public function get(string $id): object;                         // 未注册抛 NotFoundException
    public function has(string $id): bool;
}
```

- 子系统引导时向容器注册服务:`$container->singleton(EventBus::class, fn($c) => new EventBus());`
- 插件也可向容器注册服务(带 `plugin.{name}.` 前缀命名空间,避免冲突)。
- 不做自动装配(auto-wiring)以保持可预测性;控制器/服务的依赖通过 `Container` 显式获取或构造注入手写。

## 2. 事件总线(EventBus):双轨钩子

同时提供 **PSR-14 事件**(通知型,单向)与 **WordPress 式 Actions/Filters**(修改型,须返回值),覆盖两类需求。

```php
final class EventBus implements EventDispatcherInterface
{
    // PSR-14:一次性事件对象,监听者只读(可修改对象属性,无返回值约定)
    public function dispatch(object $event): object;
    public function listen(string $eventClass, callable $handler, int $priority = 0): void;

    // Action:纯通知,按 priority 顺序执行
    public function doAction(string $hook, mixed ...$args): void;

    // Filter:必须返回值,后一个监听者拿到前一个的结果
    public function applyFilters(string $hook, mixed $value, mixed ...$args): mixed;
}
```

约定:
- `priority` 默认 10;越小越先执行;相同 priority 按注册顺序。
- Filter 监听者**必须返回 `$value`**(即使不修改),否则后续链路拿到 null —— 基类断言并在开发模式抛警告。
- 事件命名:`post.published`、`comment.submitted`、`notification.ingested`(点分层级),PSR-14 类事件与字符串钩子经适配层互通(类事件同时以类名广播)。
- 内核在请求 shutdown 时派发 `app.shutdown`,通知管线借此批量投递。

## 3. 路由(Router)

PSR-7/15 风格:`Request → MiddlewarePipeline → RouteMatch → Controller`。

```php
$router->get('/', [PostWidget::class, 'home']);                  // 前台由 Widget 承接
$router->post('/api/v1/posts', [PostController::class, 'create'])
      ->middleware([AuthRequired::class, Rbac::class('post:manage')]);
$router->addRoutePoint('admin_menu', $callable);                  // 扩展点路由(见 04)
```

- 支持参数占位 `{slug}`、正则约束、命名路由反解(`route('post', ['slug'=>...])`)。
- 中间件管线:会话 → CSRF(仅状态变更) → 限流 → 维护模式 → RBAC(按路由声明)。
- 前台路由不直接映射文件,全部指向 **Widget 查询层**(见下),这是主题系统能"公开对象"的前提。

## 4. Extension 模型:一切皆注册对象

借鉴 Halo:所有业务对象统一三段结构,注册进 `ExtensionRegistry` 即自动获得仓储 + CRUD API。

```php
abstract class Extension
{
    public Metadata $metadata;   // name / uid / kind / creationTimestamp
    // spec:业务声明字段(子类定义)   status:运行时计算字段(子类可选)
}
```

| kind | 说明 | 注册方 |
|---|---|---|
| Post / Category / Tag / Page / Comment | 内容对象 | 内核 Content 子系统 |
| ThemeConfig / SettingDefinition | 主题与配置 | 主题系统 |
| PluginManifest / RouterPoint / MenuItem / SettingSection | 扩展点 | 插件系统 |
| NotificationPolicy / Template / Channel | 通知 | 通知系统 |
| User / Role / PatToken | 认证 | Auth 子系统 |

- `ExtensionRegistry` 按 kind 存储,持久化到 `extensions` 表(JSON 文档)+ 关键列冗余(便于索引)。
- **注册即 API**:每个 kind 自动生成 `/api/v1/{plural}` 的 list/get/create/update/delete,权限由 kind 声明的 RBAC 资源决定(详见 06)。
- 内置 kind 由内核注册;插件可注册新 kind(数据模型扩展点)。

## 5. Widget 查询层(主题端公开对象)

前台模板不查数据库,只消费 Widget:

```php
$posts = $app->widget('posts', ['status' => 'published', 'page' => 1, 'limit' => 10]);
$posts->items;        // Post[]
$posts->total;        // int
$posts->nextCursor;   // ?string
```

- Widget 是 Extension 查询的封装:参数即 API 的 `filter/sort/page` 参数,**同一套查询代码同时服务 REST API 与主题模板**。
- 主题端别名 `$app->api()->posts(...)` 与 `api.{group}` 命名规则见 03。

## 6. 配置三件套:ConfigMap / Options / Secret

| 存储 | 内容 | 可见性 | 示例 |
|---|---|---|---|
| ConfigMap | 非敏感键值,`config.php` + env 覆盖 | 启动时加载,只读 | DB 驱动、站点 URL 模式 |
| Options | 可变站点设置,`options` 表 | 后台/API 可读(白名单) | 站点标题、每页条数、通知默认策略 |
| Secret | 敏感凭据,`secrets` 表(可选静态加密) | **永不进 API 响应/日志** | SMTP 密码、Webhook token、PAT 哈希 |

- 读取顺序:env > ConfigMap > Options 默认值;Options 支持类型声明(bool/int/string/json)与校验规则。
- Secret 仅按 `name` 取用,列表 API 只返回元数据(名称、更新时间),不返回密文。

## 7. 引导流程(五步,Typecho 式极简)

```
1 loadConfig   读取 config.php/env,建立 PDO 连接与方言
2 boot         创建 Container,注册内核服务(单例)
3 register     ExtensionRegistry 装载内置 kind;启用主题/插件向注册表与 EventBus 挂载
4 dispatch     Router 处理请求(中间件管线)
5 render       Widget 数据 → 主题模板 / JSON 响应;shutdown 钩子
```

- 第 3 步失败(某插件抛异常)不阻断引导:该插件被标记 `failed` 并记录日志,其余继续 —— 满足"禁用全部插件后系统仍可用"。
- 安装向导唯一职责:写 ConfigMap、建表(见 07 迁移)、插入初始 admin 与默认主题注册项。

## 8. 内核公开 API 面(供子系统使用)

```php
$app->container();        // Container
$app->events();           // EventBus
$app->router();           // Router
$app->extensions();       // ExtensionRegistry
$app->options();          // Options / ConfigMap / Secret 统一门面
$app->db();               // PDO(仅 Repository 层允许直接使用)
$app->widget($kind, $q);  // 查询层
$app->logger();           // PSR-3
```

子系统之间**禁止**直接引用彼此类名,只允许:① 经容器取服务接口 ② 经 EventBus 通信 ③ 经 Widget/ExtensionRegistry 读写数据。
