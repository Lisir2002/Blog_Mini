# 09 用户系统设计(Auth 子系统)

> 用户即 Extension(`kind: User`)。核心决策(已与产品方对齐):
> ① 注册默认关闭、可选开放;② **四级权限等级(L0→L3,依次递减)+ 可自定义头衔与权限集 + 可选经验系统**;③ 高级安全特性(限流/2FA/会话管理)**本版只留接口**,后续专项讨论;④ 前台有作者页+头像署名。

## 1. 四级权限等级模型(核心创新点)

安装向导创建的第一个账号即 **L0(零级)**,拥有全部权限。默认四级对应主流 CMS 身份([WordPress Roles and Capabilities](https://wordpress.org/documentation/article/roles-and-capabilities/)):

| 等级 | 默认头衔 | 对应主流角色 | 权限概要 |
|---|---|---|---|
| L0 | 管理员 | Administrator | 全部权限 + 等级定义/系统设置/用户管理 |
| L1 | 编辑 | Editor | 管理**所有人**的文章/页面/评论;不可动系统设置 |
| L2 | 作者 | Author | 写/发/删**自己**的文章;上传媒体 |
| L3 | 订阅者 | Contributor/Subscriber | 仅评论;开放注册的新用户一律 L3 |

关键设计:**等级不是硬编码,而是 Extension(`kind: AccessLevel`)**:

```json
{ "apiVersion": "penblog.dev/v1", "kind": "AccessLevel",
  "metadata": { "name": "level-1" },
  "spec": {
    "level": 1,
    "title": "编辑",                 // 头衔可自定义(开发者/站长可改成"主编""社区元老"…)
    "title_i18n": { "en": "Editor" },
    "permissions": ["post:manage", "page:manage", "comment:moderate", "media:create"],
    "color": "#0E7490",              // 徽章色,进设计令牌体系
    "xp": { "enabled": true, "next_threshold": 500 }   // 升到本级的经验门槛(见 §2)
  } }
```

- 权限串沿用 06 §2 的 `{kind}:{action}` + 全局 `system:manage`;**L0 恒等于全集**(通配 `*`,不可删减,防自锁)。
- 插件注册的权限串(04 §5)自动出现在 L1-L3 的权限编辑器中,按插件声明的默认建议勾选。
- 每级权限集后台可勾选增删(角色模板可编辑、等级不可增删,固定 4 级——介于"固定四角色"与"完全自定义角色"之间的折中,UI 与数据模型都简单)。
- 用户与等级:users 表冗余 `level` 列(高频鉴权用),权威定义在 AccessLevel Extension。

## 2. 经验系统(可选,默认关闭)

开关 `options: auth.xp.enabled`。开启后等级可**随活跃度自动晋升**,思路取自 [Discourse Trust Levels](https://blog.discourse.org/2018/06/understanding-discourse-trust-levels/)(阅读时长/访问天数/互动计数驱动升级),但阈值全部由 L0 定义:

```json
"xp": {
  "enabled": true,
  "rules": [                                  // L0 在后台编辑
    { "metric": "reading_minutes", "per_day_cap": 30, "xp_per_unit": 1 },
    { "metric": "days_visited",    "xp_per_unit": 20 },
    { "metric": "comments_posted", "xp_per_unit": 15 },
    { "metric": "comments_received_like", "xp_per_unit": 5 },
    { "metric": "posts_published", "xp_per_unit": 40 }
  ],
  "thresholds": { "1": 200, "2": 1200 },      // 升到 L1/L2 的经验;L0 永不可自动授予
  "demotion": "none"                          // 只升不降;L0 可手动调整任何人等级
}
```

规则:
- **L0 永不自动晋升获得**(只能被 L0 手动指派);自动晋升最高到 L2。
- 经验累计走 `user_xp_events` 追加表(幂等:同事件 ID 只计一次),每日上限防刷(如阅读时长封顶)。
- 晋升时派发 `user.level.promoted` → 通知系统发 system 类通知;降级仅手动,同样留审计。
- 关闭经验系统时,等级变化只有:注册=L3、L0 手动指派。
- 评论限流等"等级副产品"(L3 每日评论数上限)由权限集 `comment:create` 的 rate 参数声明。

## 3. 注册与账号生命周期

```
注册(默认关闭;options: auth.registration = closed | open)
  open 时:用户名+邮箱+密码 → 发送验证邮件(通知系统 email 渠道)
  → 未验证账号 status=pending(可登录看自己,不能评论/发文)
  → 验证后 status=active,等级 L3;限流:同 IP 每小时 3 次注册
登录 → 会话(§4)
密码重置:输入邮箱 → 发重置链接(一次性 token,1h 有效,经通知系统)
禁用/删除:L0 操作;软删除(deleted_at),内容保留署名"已注销用户"
```

- 邮箱唯一;用户名 3-64 字符 `[a-zA-Z0-9_-]`(避免与中文 slug 混淆,显示名走 displayName)。
- 密码:`password_hash()`(Argon2id 优先,bcrypt 兜底),策略仅最小长度 8,复杂度留给后续安全专项(§6)。

## 4. 会话与令牌

| 载体 | 用途 | 实现 |
|---|---|---|
| Session | 后台 | **服务端存储**(`sessions` 表:token_hash, user_id, ip, ua, expires_at);Cookie `HttpOnly+SameSite=Lax+Secure`;登录成功即轮换 ID(防会话固定) |
| PAT | 外部程序 | 06 §2 不变;绑定创建者等级,权限=等级权限∩PAT scopes |
| JWT | 第三方应用(M5) | 短期令牌,签名密钥存 Secret |

- "记住我":延长 session TTL(30 天 vs 默认 2 小时),仍服务端可撤销。
- 鉴权中间件解析顺序:Session → Bearer(PAT) → 匿名(L3 未登录访客仅公开读)。

## 5. 用户数据模型

users 表在 M1 基础上扩展(迁移 `0002-auth`):

```
users(+ level INT DEFAULT 3, xp INT DEFAULT 0, status VARCHAR CHECK(pending|active|disabled),
      avatar VARCHAR NULL, bio VARCHAR NULL, homepage VARCHAR NULL,
      last_active_at TIMESTAMP NULL, deleted_at TIMESTAMP NULL)
sessions(id, token_hash UNIQUE, user_id FK, ip, user_agent, expires_at, created_at)
user_xp_events(id, user_id, metric, amount, event_key UNIQUE, created_at)   -- 幂等追加
```

- 用户 Extension 的 `spec` 即上列可编辑字段,`status` 计算列:level 头衔、xp、是否需验证。
- 公开只读 DTO(主题/API 可见):`displayName, avatar, bio, homepage, 头衔徽章`;email/password_hash 永不出现在任何非本人响应。

## 6. 预留安全接口(本版只定义,不实现)

```php
interface LoginThrottleHandler { public function check(string $ip, string $username): bool; }   // 接口注入,默认直通
interface TwoFactorHandler     { public function verify(User $u, string $otp): bool; }           // 默认 null
interface SessionManager       { public function listForUser(int $uid): array; public function revoke(...); }
interface EmailChangeVerifier  { public function request(User $u, string $newEmail): void; }
```

- 内核按容器取用,未注册实现即跳过 —— 后续安全专项只需注册新实现,零改动核心。
- 这保证"留空接口,后续单独聊"不落空:表结构(sessions 有 ip/ua)与钩子点已为此备好。

## 7. 作者存在感(前台)

- 路由:`/authors/{username}` → 作者归档页(头像+bio+主页链接+TA 的已发布文章分页),数据走 Widget `posts(author=name, status=published)`。
- 主题端:`$app->api()->users(['author' => 'name'])` 返回公开 DTO;文章署名行渲染头像+头衔徽章(等级 color 令牌)。
- 评论显示评论者 displayName+头像(L0-L2 带等级徽章,防冒充用官方 @ 格式)。

## 8. API 面(并入 06 的自动 CRUD 之外)

```
GET/PUT  /api/v1/user/me                    # 本人资料(含 email)
POST     /api/v1/auth/register              # 开放注册时(限流)
POST     /api/v1/auth/login / logout
POST     /api/v1/auth/password-reset        # 请求(邮件) / 完成(token)
GET      /api/v1/access-levels              # 等级定义(公开头衔与徽章色,权限列表仅 L0 可见)
PUT      /api/v1/users/{name}:level         # L0 手动调整等级
GET      /api/v1/users/{name}/stats         # xp/等级统计(本人+L0)
```

## 9. 与其他子系统的接缝

| 依赖方 | 接缝 |
|---|---|
| 通知系统 | recipient 支持 `user:{name}` / `level:{n}` / `role:admins`;验证/重置邮件走 email 渠道;晋升通知走 system |
| 插件系统 | 插件权限串并入等级编辑器;插件可申请 `user.xp.grant` 权限上报经验事件 |
| 主题系统 | users 公开对象白名单(§5 DTO);作者页保底 fallback 模板 |
| API | PAT 权限=等级权限∩scopes;`filter[level]` 可查同等级用户(仅 L0) |

## 10. 落地排期

- **M2**:`0002-auth` 迁移 + AccessLevel Extension + 鉴权中间件(Session/PAT) + 登录登出 + user/me
- **M3**:等级编辑器 UI + 注册流程(含邮件验证,依赖 M4 通知,先做 pending 状态)
- **M4**:验证/重置邮件接通;作者页进默认主题
- **M5**:经验系统(开关+规则 UI+xp_events);§6 安全专项另行设计
