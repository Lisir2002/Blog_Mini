# 10 安装向导设计(自研 Install Bootstrapper)

> 调研结论:Typecho 首访自动进向导、SQLite 零配置一步到位([Typecho 网页安装](https://developer.cloud.tencent.cn/article/2666267));Halo 首次访问单页初始化站点标题+管理员,点完即进后台([Halo 初始化](https://help.aliyun.com/en/simple-application-server/use-cases/deploy-the-halo-open-source-website-building-tool));Ghost 走交互式 CLI(`ghost install`)。
> 自研方案吸收三点:**首访即向导、默认零配置、一屏完成**;并补上主流方案的短板(环境检测滞后报错、无失败恢复、CLI/Web 行为不一致)。

## 1. 双通道,同一内核

```
InstallService(唯一权威实现)
├── Web 向导(/install)      # 人类:浏览器首访
└── CLI(bin/install.php)    # 脚本:Docker entrypoint / CI / SSH 手动
```

- 两个通道调用**同一个 InstallService::run(InstallPlan)**(环境自检→建库→迁移→种子→写配置),保证行为一致、可测试。
- Docker 场景:环境变量 `PENBLOG_*`(02 ConfigMap 已支持)驱动 CLI,零交互。

## 2. 安装守卫(Install Guard)

- 内核 boot 时 `config/config.php` 不存在 → 进入 **installing 模式**:除 `/install` 与静态资源外,所有路由返回 302 跳向导;API 返回 503 `not_installed`(M1 已有雏形,补齐路由)。
- 安装完成(配置文件落盘)→ `/install` 路由**整体注销**(404),不提供任何重装入口;重装只能经 CLI `--force`(需先手动删除 config,防误操作/防外部重置)。
- 写配置原子性:临时文件 + rename;`config.php` 权限 0640。

## 3. Web 向导三步流(单页应用式,原生 JS 渐进增强)

### 步骤 1:环境自检(全绿才放行,失败项给出修复指令)

| 检查项 | 失败示例文案 |
|---|---|
| PHP ≥ 8.2 | "当前 8.1,请升级"(附各系统升级命令) |
| 扩展 pdo_mysql / pdo_sqlite / mbstring / json | "缺少 mbstring:php-mbstring" |
| `storage/` `config/` 可写 | 附 `chown -R www-data:www-data storage` |
| SQLite 文件可创建 / MySQL 可连接(advanced 选了才测) | 连接错误原样展示 |
| 建议项(非阻断):OPcache、URL rewrite | 黄色警告,可忽略继续 |

- 自检为纯只读探测,可反复重试;结果缓存 60s。

### 步骤 2:配置(一屏,默认路径零思考)

```
站点标题 [________]   站点 URL [自动检测,可改]
数据库:  (•) SQLite 零配置(推荐,个人博客)     ← 默认选中
         ( ) MySQL  [主机][端口][库名][用户][密码]  ← 折叠,展开才校验
管理员:  用户名 [admin]  邮箱 [____]
         密码 [________] [🎲 生成强密码] [一键复制]
         (•) 安装完成后自动登录我
高级(折叠):表前缀 / 开发模式开关
```

- 密码留空则自动生成 16 位强密码并在完成页展示(仅展示这一次)。
- 提交带一次性 CSRF token;服务端全量重校验(浏览器禁用 JS 时表单照常可用)。

### 步骤 3:执行与完成

- 进度页逐条显示:`建库 → 迁移(0001/0002) → 写入 L0 账号+默认 Options → 注册默认主题 → 写 config.php`;每步幂等,失败即停并回滚已完成步骤(迁移本身有事务)。
- 完成页:站点信息摘要(用户名/密码/配置文件路径)+ **进入后台**按钮(自动登录会话直接落地后台仪表盘)+ 下一步引导(上传第一篇文章/更换主题)。

## 4. 种子数据(InstallPlan 固定内容)

| 写入 | 内容 |
|---|---|
| users | L0 管理员(password_hash) |
| AccessLevel Extensions | L0-L3 四级默认头衔与权限集(09 §1) |
| Options | site.title/url、auth.registration=closed、active_theme=default、通知默认策略(05 §4 系统默认层) |
| Extensions | 默认主题注册项、示例文章一篇("Hello PenBlog",可一键删除) |
| Secret | app.secret_key 随机 32 字节(写入 config.php) |

## 5. 升级与修复(安装器的孪生流程)

- 版本比对:`config.php` 记录 `penblog_version`;后台检测到新版本 → 维护模式横幅 → CLI `bin/console migrate`(Web 端同调用 InstallService 的 UpgradePlan:先自动备份 `storage/backups/时间戳.db` 再跑增量迁移,失败自动回滚)。
- 修复模式:`bin/install.php --repair` 重跑环境自检与缺失迁移,不改用户数据。

## 6. 安全红线

- 安装期窗口最短化:自检+配置两步之间不写任何数据;config 落盘瞬间 `/install` 注销。
- 向导页面不暴露 PHPinfo 全量,仅展示检查项结果。
- 管理员密码不回显(除非用户点"生成"),完成页展示后提示"此后不可恢复查看"。
- 限流:/install POST 每 IP 10 次/小时。

## 7. 实现排期

- **M2**:InstallService + Install Guard + CLI 重构(现 bin/install.php 拆为 Service 调用)+ 环境自检
- **M3**:Web 向导三步页(复用主题系统 fallback 模板渲染,后台样式令牌)
- **M5**:升级/修复流程 + 自动备份
