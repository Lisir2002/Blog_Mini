# 04 插件系统设计

> 目标:给用户更高的自定义权限能力。机制:**manifest 声明 + 生命周期 + 扩展点注册 + 钩子订阅**,并保证"禁用全部插件后系统仍可用"。

## 1. 插件结构

```
plugins/seo-tools/
├── plugin.json        # manifest(必需)
├── src/               # PSR-4: SeoTools\
│   └── Plugin.php     # 入口类,实现 PluginInterface
└── assets/            # 可选静态资源(经 /plugin-assets/{name}/ 暴露)
```

```json
{
  "name": "seo-tools",
  "version": "1.2.0",
  "requires": { "penblog": ">=1.0", "php": ">=8.2" },
  "entry": "SeoTools\\Plugin",
  "permissions": ["router.register", "option.read", "event.listen"],
  "secretRefs": ["yandex_token"],
  "description": "..."
}
```

## 2. 生命周期

| 动作 | 行为 |
|---|---|
| install | 校验 manifest 与 `requires`;入口类可加载自检;注册 `kind: PluginManifest`,状态 `installed` |
| activate | 实例化入口类 → 调 `onActivate(PluginContext $ctx)` → 其注册项进入注册表;状态 `active` |
| deactivate | 调 `onDeactivate()` → **撤销该插件全部注册**(路由/菜单/监听器/扩展点),状态 `inactive` |
| uninstall | 调 `onUninstall()` → 清 `plugin.{name}.*` Options 与 Secret;文件保留待确认 |

- 引导顺序按依赖拓扑(`requires.plugins`)+ 激活顺序;循环依赖拒绝激活并告警。
- 插件 `onActivate` 抛异常 → 标记 `failed`,不影响其他插件与内核(同 02 §7)。
- **注册可撤销性**是硬约束:所有注册 API 都返回句柄,deactivate 时统一回收 —— 这保证禁用后系统回到纯净状态。

## 3. PluginContext:插件唯一的权力入口

```php
interface PluginContext
{
    public function events(): EventBus;                       // doAction/applyFilters/listen
    public function registerRoute(string $method, string $path, callable $h, string $rbac): void;   // RouterPoint
    public function registerMenuItem(string $area, MenuItem $item): void;                            // 后台/前台菜单
    public function registerSettingSection(SettingSection $s): void;                                 // 声明式配置面板
    public function registerExtension(string $kind, bool $public): void;                             // 新数据模型
    public function options(): OptionsScope;                  // 限定 plugin.{name}.* 命名空间
    public function secrets(): SecretScope;                   // 仅 manifest 声明过的 secretRefs
    public function logger(): LoggerInterface;
}
```

- 插件**不接收** Container/Router/DB 原始对象;能力只经 Context 的窄接口,权限在 `permissions` 声明,未声明的调用抛 `PermissionDenied`。
- Options/Secret 强制命名空间隔离,防止插件互相踩踏。

## 4. 扩展点(Extension Points)清单

核心预留、插件可挂载的注册点:

| 扩展点 | 用途 | 示例 |
|---|---|---|
| RouterPoint | 注册前台/后台/API 路由 | 自定义 `/sitemap.xml` |
| MenuItem | 后台设置页、前台导航追加项 | SEO 设置入口 |
| SettingSection | 声明式配置区块(复用 03 §5 渲染器) | 站点验证代码块 |
| APIEndpoint | 注册 `/api/v1/{group}/...` 自定义端点 | 批量导出接口 |
| ExtensionKind | 注册新数据模型,自动获得 CRUD API | `kind: Redirect` |
| WidgetFilter | 包装/增强查询结果 | 列表附加 SEO 字段 |
| Hook 点(Actions/Filters) | 见下表 | — |

内核核心钩子点(节选):

```
doAction:  post.published / post.deleted / comment.submitted / comment.held_for_moderation
           user.registered / theme.activated / plugin.activated / notification.delivered
applyFilters: post_content / comment_allow / api_response / theme_tokens / menu_items
```

## 5. 权限与安全模型

- **RBAC 资源声明**:插件注册路由/端点时必须带权限串(如 `seo:manage`),激活时自动并入角色模板(见 06 §4),卸载时移除。
- **Secret 隔离**:凭据只经 `secrets()` 存取,永不出现在 Options、API 响应、日志(内核日志层做 redaction)。
- **无沙箱进程,但有红线**:插件代码与内核同进程运行(PHP 常规做法),红线靠:① Context 窄接口 ② permissions 声明校验 ③ 输出转义由渲染层兜底 ④ 市场审核机制(M5)。
- 插件静态资源经统一路由暴露,禁止直接暴露插件目录。

## 6. 插件间协作

- 插件 A 想扩展插件 B:只能经 B 公开的钩子名(B 在 manifest 声明 `providesHooks`),不允许直接 new B 的类。
- 事件总线命名空间约定:`plugin.{name}.{event}`,监听方按前缀订阅。

## 7. 与主题系统的边界

- 主题=外观与模板;插件=行为与数据扩展。主题不得注册路由/扩展点;插件不得提供模板覆盖(需要改模板 → 做子主题)。
- 需要"插件出前台页面":经 RouterPoint + Widget 渲染保底模板,或引导用户装配套主题。

## 8. 管理体验

- 后台插件页:列表(状态/版本/依赖)、上传安装、启停、配置跳转(SettingSection 自动出现)。
- 故障可见:`failed` 插件展示错误摘要与日志尾行,一键重试激活/卸载。
