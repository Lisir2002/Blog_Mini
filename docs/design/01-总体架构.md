# 01 总体架构设计

## 1. 分层架构

```
┌─────────────────────────────────────────────────────────┐
│ 接入层    主题前台(渲染)  管理后台(Admin)  REST API v1   │
├─────────────────────────────────────────────────────────┤
│ 核心引擎  Router → 中间件管线 → 服务容器 → 事件总线      │
│ Kernel    Extension 注册中心 → Widget 查询层 → 仓储抽象  │
├─────────────────────────────────────────────────────────┤
│ 子系统    主题系统  插件系统  通知系统  内容管理  认证RBAC │
├─────────────────────────────────────────────────────────┤
│ 数据层    PDO(MySQL/SQLite)  Options存储  缓存  文件系统  │
└─────────────────────────────────────────────────────────┘
```

依赖方向自上而下单向:子系统只能依赖内核,内核不依赖任何子系统;跨子系统通信一律走事件总线。

## 2. 请求生命周期

```
public/index.php
  → Kernel::boot()            # 加载配置、注册自动加载、引导服务容器
  → MiddlewarePipeline        # 会话、CSRF、限流、维护模式
  → Router::dispatch()        # 匹配路由 → Controller/Widget
  → Controller                # 调用子系统服务,派发事件
  → ThemeRenderer             # 主题模板渲染(前台)/ JSON(后台与 API)
  → Response                  # 统一输出、事件 shutdown 钩子
```

## 3. 目录结构(规划)

```
penblog/
├── public/index.php          # 唯一 Web 入口
├── src/
│   ├── Kernel/               # 内核:Container、EventBus、Router、Extension
│   ├── Content/              # 内置内容子系统:Post/Category/Tag/Page/Comment
│   ├── Auth/                 # 用户、RBAC、会话、PAT
│   ├── Theme/                # 主题系统
│   ├── Plugin/               # 插件系统
│   ├── Notification/         # 通知系统
│   ├── Repository/           # PDO 仓储抽象(双方言)
│   ├── Http/                 # Request/Response/中间件
│   └── Support/              # 通用工具:Arr、Str、Env、Logger
├── themes/default/           # 主题目录
├── plugins/                  # 插件目录
├── storage/                  # data.db / cache / uploads / logs
├── config/                   # config.php(生成)、routes.php
├── tests/                    # Unit / Integration / Functional
└── composer.json
```

Web 根目录只暴露 `public/`;`src/`、`storage/`、`config/` 均在 Web 根之外。

## 5. 双引擎兼容策略

- 仓储层是唯一允许出现方言差异的地方:`SqlDriver` 接口 + `MysqlDriver` / `SqliteDriver`。
- 差异点清单:`AUTO_INCREMENT` vs `AUTOINCREMENT`、`NOW()` vs `datetime('now')`、`ENUM` vs `TEXT+CHECK`、`utf8mb4` 字符集、UPSERT(`ON DUPLICATE KEY` vs `ON CONFLICT`)、FTS(各自全文索引方案)。
- 上层业务 SQL 一律使用仓储方法(如 `repo->insertReturningId()`),不手写方言语句。
- 默认安装选 SQLite(零配置),生产可一键切换 MySQL。

## 6. 非功能要求

| 项 | 目标 |
|---|---|
| 性能 | 前台页 P95 < 200ms(SQLite,1k 文章量级);索引覆盖列表查询 |
| 安全 | 预处理语句 100%、输出转义、CSRF、RBAC、密码 Argon2id/bcrypt |
| 可插拔 | 禁用全部插件后系统仍可正常读写与渲染 |
| 可测试 | 内核与子系统单元测试覆盖 > 80%,集成测试用内存 SQLite |
| 可观测 | PSR-3 日志 + 通知状态机全程留痕 + 错误页与日志分离 |
